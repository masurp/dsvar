Setup · before week 1

Before the first work group

Every work group runs on your own laptop, in R and RStudio. The first half of this page is a checklist to work through at home before Thursday of week 1. The second half is for the moments when the computer gets in the way instead of R: a download you cannot find, a zip that will not open, a file R says does not exist, a key you cannot type.

BEFORE THURSDAY OF WEEK 1

1

Two minutes

Check your laptop

A Windows laptop (Windows 10 or 11) or a Mac works. A Chromebook, an iPad, or a work laptop on which you are not allowed to install software will not run RStudio. If that is your situation, say so on Canvas before the course starts.

2

About twenty minutes

Install R, then RStudio

R is the program that runs your code. RStudio is the program you work in; it starts R for you. Both are free. Install R first. If you already have R, check the version on the first line of the console: the course needs 4.4 or higher. If yours is older, install the new one in the same way.

  • Windows
  • macOS
  1. Go to cran.r-project.org, click Download R for Windows, then base, then the download link at the top.
  2. Open the downloaded .exe file and click through, keeping every default. If Windows asks whether the app may make changes to your device, click Yes.
  3. Go to posit.co/download/rstudio-desktop and download RStudio Desktop for Windows. Open it and keep every default.
  4. Open RStudio from the Start menu: press Win, type RStudio, press Enter.
  1. Check which chip your Mac has: the Apple menu (top left) > About This Mac. It says either Chip: Apple M… or Processor: … Intel.
  2. Go to cran.r-project.org and click Download R for macOS. With an Apple chip, take the installer whose name ends in arm64.pkg; with Intel, the one ending in x86_64.pkg. The wrong one installs fine and then causes trouble later, so check twice.
  3. Open the .pkg file and click through.
  4. Go to posit.co/download/rstudio-desktop and download RStudio Desktop for macOS. Open the .dmg file and drag the RStudio icon into the Applications folder in that window. Then eject the RStudio disk in the Finder sidebar.
  5. Open RStudio from Applications, or press Cmd + Space, type RStudio, press Enter. If macOS asks whether you are sure you want to open an app downloaded from the internet, click Open.

Done when the console (the pane at the bottom left) starts with R version 4.4 or higher, and typing 1 + 1 there and pressing Enter prints [1] 2.

3

Two minutes

Change three settings in RStudio

Open Tools > Global Options.

  • Under General, untick Restore .RData into workspace at startup, and set Save workspace to .RData on exit to Never. Every session then starts empty, so your code has to work from top to bottom on its own, which is what happens when someone else runs it.
  • Under Code, tick Use native pipe operator, |>. The shortcut Ctrl + Shift + M (Cmd + Shift + M on a Mac) then types the pipe the work groups use.

Click OK.

4

Ten to twenty minutes, on a good connection

Install the course packages

Packages add functions to R. This line installs every package the work groups use, so no work group has to start with a download. Copy it (the button at the top right of the box does that) into the RStudio console and press Enter:

install.packages(c("tidyverse", "ggdist", "ggrepel", "zoo", "maps",
                   "tidygraph", "ggraph", "tidytext", "janeaustenr",
                   "colorspace", "patchwork"))

The tidyverse is what week 1 needs; it brings ggplot2, which draws every chart in this course. The others are for weeks 3 to 7, in the order the weeks use them.

A lot of red text scrolls past. That is normal: R prints its progress in red. It is finished when the > prompt is back at the bottom of the console.

If R asks Do you want to install from sources the packages which need compilation?, type no and press Enter. If it asks whether to use a personal library, answer yes both times. What these questions mean.

5

Five minutes

Run the setup check

Paste these lines into the console and press Enter. The first three are the ones the week 1 work group starts with.

library(tidyverse)          # a list of packages with ticks: that is normal
R.version.string            # 4.4 or higher
packageVersion("ggplot2")   # 3.5 or higher; the course is written on 4.0
ggplot(mpg, aes(x = displ, y = hwy)) + geom_point()   # a chart, under Plots

Then check the packages for the later weeks:

later <- c("ggdist", "ggrepel", "zoo", "maps", "tidygraph", "ggraph",
           "tidytext", "janeaustenr", "colorspace", "patchwork")
sapply(later, requireNamespace, quietly = TRUE)   # TRUE under every name

Last, Quarto, which turns a .qmd file into a web page. It comes with RStudio, so there is nothing more to install. Click the Terminal tab next to Console (not the console itself), type quarto check and press Enter. Look for Checking R installation … OK and, on the last line, Checking Knitr engine render … OK. What it says about Python, Jupyter or LaTeX does not matter: this course uses none of them.

Done when no line gives an error, both version numbers are high enough, a scatterplot appears in the Plots pane at the bottom right, every package says TRUE, and quarto check ends in OK.

If something fails, say so on Canvas before Thursday and paste what R printed, as text. Arriving with a broken install is fine; arriving with one and not saying so is not.

6

Five minutes · you do this every week

Make your dsvar folder, and open week 1 in it

Make a folder called dsvar in Documents, not in Downloads. Every week’s folder goes into it, so all your work lives in one place.

  1. Download the week 1 folder (button below). It arrives as a zip file.
  2. Unzip it into dsvar. On Windows: right-click the zip > Extract All, and choose dsvar. On a Mac: double-click it, then move the folder that appears into dsvar. More on zip files.
  3. Double-click dsvar-week-01.Rproj. RStudio opens with this folder as its working directory, so the code can say "data/…" without a full path. Why that matters.
  4. Open workgroup-01.qmd (in the Files pane, bottom right) and click Render. If a page appears, R, Quarto, the course theme and the data all work.

Every later week works the same way: download its folder from that week’s work group page, unzip it into dsvar, double-click its .Rproj. If you do not get this far at home, it is the first thing on Thursday.

Download the week 1 folder

7

Five minutes

Can you do these ten things?

In the first work groups, most time is lost on things around R: a file in the wrong folder, a zip that was never unzipped, or a key nobody can find. If you hesitate on any of these, read the part of this page it links to.

  1. Find a file you just downloaded, without searching the whole computer. (Downloads)
  2. Unzip a zip file into a folder you chose. (Zip files)
  3. See whether a file ends in .csv, .qmd, .Rproj or .zip. (File extensions)
  4. Say where your dsvar folder is, and whether it syncs to the cloud. (Your dsvar folder)
  5. Open a week’s folder so that RStudio works inside it. (Paths and projects)
  6. Explain why read_csv("data/file.csv") works in one place and not in another. (Paths and projects)
  7. Run one code chunk of a .qmd file, then one single line. (RStudio in five minutes)
  8. Type |, ~, {, [ and " on your own keyboard. (Keyboard)
  9. Switch from your browser to RStudio without the mouse, and take a screenshot of part of the screen. (Keyboard)
  10. Stop R when it seems stuck, and tell what a + in the console means. (RStudio in five minutes)

DOWNLOADS

Your browser saves files to the Downloads folder unless you told it otherwise. To find the file you just downloaded, click the download icon (an arrow) at the top right of the browser, then Show in folder (Windows) or the magnifying glass (Mac). On Windows, Ctrl + J opens that list in most browsers.

  • Downloading the same file twice gives week-01 (1).zip. Delete the old one, or you will not know which one you unzipped.
  • Downloads is a place files pass through. Do not work in it: unzip what you need into your dsvar folder.

ZIP FILES

A zip file packs several files into one, so a week’s folder can be one download. Before you can use the files, they have to be unzipped (Windows calls it extracting).

  • Windows
  • macOS

Double-clicking a zip shows what is inside, but unzips nothing. Code you open from there cannot find its data, and whatever you save is lost. Working inside the zip is the most common reason R cannot find a file. Instead:

  1. Right-click the zip > Extract All…
  2. Click Browse and choose your dsvar folder, then Extract.

It worked when dsvar holds an ordinary folder dsvar-week-01, without a zipper on its icon, and the .Rproj file is directly inside it.

Double-click the zip in Finder. It is unzipped into a folder next to the zip. Move that folder into dsvar.

Safari unzips files by itself after downloading, so you may find a folder in Downloads rather than a zip. That folder is what you need.

FILE EXTENSIONS

The last part of a file name, after the dot, says what kind of file it is: .csv is a table, .qmd a Quarto document, .Rproj an RStudio project, .zip a packed folder. Windows and macOS hide it by default, which makes week-01.zip and the folder week-01 look alike. Make the extensions visible:

  • Windows
  • macOS

In File Explorer, open View > Show and tick File name extensions (Windows 11). On Windows 10, open the View tab and tick File name extensions.

In Finder, open Finder > Settings > Advanced and tick Show all filename extensions.

Two traps this prevents:

  • Renaming without seeing the extension turns data into data.csv.csv, and R cannot find data.csv.
  • Saving a .csv from Excel. Opening one in Excel to look at it is fine. Saving it is not: on a Dutch or German computer Excel writes semicolons instead of commas and decimal commas instead of points, and it can change dates and long numbers. This matters most in week 7, when you bring a file of your own. Look at data in RStudio instead: View(), or click the table in the Environment pane.

If double-clicking a .Rproj or .qmd file opens the wrong program, open RStudio first and use File > Open Project or File > Open File. To make RStudio the default: on Windows, right-click the file > Open with > Choose another app > RStudio, Always; on a Mac, select the file, press Cmd + I, choose RStudio under Open with and click Change All.

YOUR DSVAR FOLDER

One folder for the course, Documents/dsvar, with every week’s folder unzipped into it. After two weeks it looks like this:

dsvar/
├── dsvar-week-01/
│   ├── dsvar-week-01.Rproj
│   ├── theme-dsvar.R
│   ├── data/
│   │   └── knmi-de-bilt-monthly.txt
│   └── workgroup-01.qmd
└── dsvar-week-02/
    ├── dsvar-week-02.Rproj
    ├── theme-dsvar.R
    ├── data/
    │   └── worldbank-indicators.csv
    ├── week-02-part1.qmd
    └── week-02-part2.qmd

Each week’s folder carries everything its work group and its portfolio entry need: the data, the course theme and the files you write in. From week 2 there are two: part1 for the example you work through with the teacher, and part2, your portfolio entry and the only file you hand in. Week 1 hands nothing in, so the entries run one behind the weeks: week 2’s Part II is portfolio entry 1.

  • Keep each folder as it came. The code expects data/ and theme-dsvar.R next to the .qmd. Moving files around inside a week’s folder breaks that.
  • Cloud folders. On many laptops Documents is synced to OneDrive (Windows) or iCloud Drive (Mac). That is fine, with one setting: synced files can live only in the cloud until you open them, and R cannot always read those. Right-click your dsvar folder and choose Always keep on this device (OneDrive) or Keep Downloaded (iCloud).
  • Names. File and folder names without spaces and special characters save typing and mistakes: notes_week03.qmd, not Week 3 notes (final!).qmd.

PATHS AND PROJECTS

A path is the address of a file: the route through the folders to get to it. R looks for files in one folder at a time, the working directory, and a path like "data/worldbank-indicators.csv" starts from there.

  • Double-clicking a week’s .Rproj opens it as a project: the working directory is that week’s folder, for the console and for every file in it. The project’s name shows at the top right of RStudio. That is why the code can say "data/…" without a full path.
  • In a .qmd file, the working directory is the folder the .qmd is in, both when you run a chunk and when you click Render.
  • In the console without a project, it is usually your home folder. A line that works in a chunk then fails in the console, or the other way round. Open the project, and the two agree.
  • To check: getwd() prints the working directory, list.files() the files in it.
  • Avoid setwd("C:/Users/...") and full paths in general. A line with C:/Users/sam/... in it runs on Sam’s laptop and nowhere else, and every entry has to render on someone else’s machine, and whoever grades it actually tries. If you paste a Windows path anyway, R reads each \ as the start of a special character: replace every \ with /.

A shortcut that prevents typos: type read_csv(" and press Tab. RStudio lists the files in the working directory; type the first letters and press Tab again. If the file is not in the list, R will not find it either.

INSTALLING SOFTWARE

What you might see, and what to do.

R asks Do you want to install from sources the packages which need compilation? (Yes/no/cancel). Answer no. The newest version of a package is sometimes not yet prepared (“compiled”) for your system. Yes means your computer has to compile it, which needs extra tools you probably do not have. No gives you the previous, ready-made version, which is fine.

R asks Would you like to use a personal library instead?. Answer yes, and yes again when it offers to create one. Packages then go into a folder of your own.

R warns Rtools is required to build R packages (Windows). Ignore it. You only need Rtools to compile packages, see above.

R warns package ‘ggplot2’ was built under R version 4.x.y. Harmless. It means your R is a little older than the package; it goes away when you next update R.

Error: there is no package called ‘ggrepel’. The package is not installed. Run install.packages("ggrepel") once, or the whole line from step 4 again.

Error: could not find function “ggplot”. The package is installed but not loaded in this session, or the name has a typo. Run the library(...) lines at the top of the file. Installing happens once per computer; library() once per session.

packageVersion("ggplot2") says less than 3.5. Run install.packages("ggplot2"). If it stays old, your R is too old to get the new version: update R first, as below.

Your R is older than 4.4. Install the current version the same way as the first time, then run the package line from step 4 again: packages belong to one R version. RStudio updates itself through Help > Check for Updates.

quarto check gives Error: unexpected symbol. You typed it in the console. It belongs in the Terminal tab next to it.

quarto check says the command is not found. Your RStudio is too old to include Quarto. Update it through Help > Check for Updates, or download it again from posit.co.

Mac: RStudio is gone after a restart, or there is an RStudio disk in the Finder sidebar. You ran it from the download instead of installing it. Drag RStudio into Applications, then eject the disk.

Mac: you are not sure you took the right R. Type R.version$arch in the console. On an Apple chip it should say aarch64. If it says x86_64, download the installer ending in arm64.pkg from CRAN, install it over the old one, restart RStudio and run the package line from step 4 again.

RSTUDIO IN FIVE MINUTES

RStudio has four panes. Top left is the editor, where your .qmd file is open. Bottom left is the console, where R runs things and prints the results; next to it, the Terminal talks to your computer instead of to R (you need it once, for quarto check). Top right, Environment lists the objects you have made. Bottom right, Files shows the working directory, and Plots and Help appear there too.

A .qmd file mixes text with grey code chunks. Three ways to run code:

  • One line: put the cursor on it and press Ctrl + Enter (Cmd + Enter on a Mac). The cursor moves to the next line, so you can step through a chunk.
  • One chunk: click the green ▶ at its top right.
  • Everything above: the small grey ▼ next to the ▶ runs all chunks before this one. Use it when R says an object does not exist because you skipped a chunk.

Render runs the whole file from the top in a fresh session and makes a web page of it. If a file renders with an error but worked when you ran it chunk by chunk, it depended on something you did in the console.

What the console is telling you:

  • > means R is ready.
  • + means R is waiting for you to finish a command, usually a missing ) or ". Press Esc to start over.
  • A small red stop sign at the top right of the console means R is busy. Wait, or press Esc to interrupt it.

When things behave oddly, restart R (Session > Restart R) and run the file again from the top.

Characters R needs that your keyboard may hide

On a US or UK keyboard, |, ~, {, [ and \ are printed on the keys. On other layouts they sit behind a modifier key. The ~ is the one you meet first, in facet_wrap(~ month).

Character German, Windows German, Mac
| AltGr + < Option + 7
~ AltGr + + Option + N, then Space
{ } AltGr + 7 / 0 Option + 8 / 9
[ ] AltGr + 8 / 9 Option + 5 / 6
\ AltGr + ß Option + Shift + 7

For any other layout: on Windows, open the On-Screen Keyboard (press Win, type it) and hold AltGr to see what appears; on a Mac, turn on Show Input menu in menu bar under System Settings > Keyboard > Text Input, choose Show Keyboard Viewer from that menu, and hold Option.

The US-International trap. Many laptops in the Netherlands use the US-International layout. On it, ", ', `, ~ and ^ wait for the next key to make é or ë, so typing read_csv("export.csv") can give read_csv(ëxport.csv"). Press Space after the quote to get the quote itself, or switch to the plain US layout (ABC or U.S. on a Mac), which has no such keys.

WHEN SOMETHING GOES WRONG

Read the error first. Its last lines usually name the problem, and ggplot2 and dplyr often say what you probably meant:

R says What it usually means
object 'July' not found The line that makes it has not run yet in this session, or the name has a typo. Capitals count. Run the chunks above (the grey ▼).
could not find function "..." The package is not loaded: run the library() line. Or a typo.
'data/file.csv' does not exist in current working directory R is looking in another folder than the file is in. Did you open the week’s .Rproj? Is the zip unzipped? See Paths and projects.
there is no package called '...' Not installed yet. See Installing software.
Cannot use + with a single argument A + at the start of a line. In a ggplot, the + goes at the end of the line before.
`mapping` must be created by `aes()` A pipe between ggplot layers. Layers are added with +; the pipe |> only leads into ggplot().
We detected a named input An = inside filter(). Comparing is ==.
unexpected symbol, unexpected ')' A typo: often a missing comma or bracket, on that line or the one before.
unexpected invalid token, unexpected input Often curly quotes, see below.

Curly quotes. Code copied from a PDF, Word or slides often turns " into “ and ”, which R does not accept. Retype the quotes in RStudio, or copy code from the course website with the copy button at the top right of each code box.

Restart and run again. Session > Restart R, then run the file from the top. Many puzzling errors come from leftovers of an earlier attempt.

Asking for help. Say what you ran, what you expected, and paste the error as text, not a photo of your screen. For a screenshot, use Win + Shift + S or Cmd + Shift + 4, then Space. If it is about installing, add what the setup check printed.
