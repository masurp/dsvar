A decision tree

Field guide

The idea behind this field guide is to help you choose the right type of chart for your specific data. What kind of variable(s) you have and what you want to show with them decides which types of chart you can use. Pick the variable kind below and follow the branches to the relevant charts. Every form opens onto what it claims and the R code that draws it.

Categories from week 2

Counts of things, and parts of a whole. Every variable here is categorical; the only number is how many fall in each category.

  • One categorical variable
    • Bar chart of counts
    • Lollipop chart
    • Waffle chart
    • Think twicePie chart
  • Two categorical variables
    • Compare inside each group
      • Grouped bars
    • The make-up of each group
      • Stacked to 100%
    • Every combination at once
      • Count grid
    • The same cases, followed across
      • Alluvial flows

Category & number from week 2

One categorical variable and one continuous one: the simplest chart there is, and the commonest. The first question is whether each category has one value, two, or many.

  • One value per category
    • Rank them
      • Sorted bars
      • Dot plot
    • Against a reference
      • Diverging bars
    • Parts of a whole, nested
      • Treemap
  • Two values per category
    • Slopegraph
    • Dumbbell
  • Many values per category
    • Show every point
      • Strip plot
      • Raincloud
    • Show the shape
      • Violin
      • Ridgeline
    • Summarise each group
      • Box plot
      • Think twiceMean and interval
      • Think twiceBar with error bars

Numbers from week 3

Continuous variables only. One of them is a distribution, two are a relationship, and several are a search for which relationship to argue about. One estimate, made many defensible ways, is a test of whether the argument survives.

  • One variable
    • Histogram
    • Density curve
  • Two variables
    • Tens to hundreds of points
      • Scatterplot
      • Scatter with a fitted line
      • Bubble chart
    • Thousands of points
      • Transparent scatter
      • 2D bins
  • Several variables
    • Small multiples
    • Scatterplot matrix
    • Correlation heatmap
    • Think twiceRadar chart
  • One effect, estimated many ways
    • Specification curve

Time from week 5

One variable is time, and time is ordered. That order is the whole reason a line is allowed here and nowhere else on this page.

  • One series
    • Through time
      • Line chart
      • Line with a smoother
      • Area chart
      • Warming stripes
    • Around a cycle
      • Seasonal grid
      • Think twiceRose diagram
      • Think twiceRadar chart
  • Several series
    • On the same units
      • Several lines
      • Small multiples
    • Parts of a total
      • Think twiceStacked area
  • Two series against each other
    • Connected scatterplot
    • Think twiceTwo y axes

Space from week 6

The data has a place attached. The first question is whether the value belongs to an area, to a point or to a route between two, and the second is whether it is a count or a rate.

  • A value for each area
    • Drawn as the land is
      • Choropleth
    • Every area the same size
      • Tile map
  • Values at places
    • A count at each place
      • Proportional symbols
    • Each event where it happened
      • Point map
  • Movement between places
    • Flow map

Networks & text from week 6

Connections between things, and words. Both turn out to be applications of forms met earlier: a matrix is a heatmap, a word count is a sorted bar chart, and a word embedding is a scatterplot.

  • Connections
    • A few hundred nodes or fewer
      • Node-link diagram
    • Dense, or many nodes
      • Adjacency matrix
    • Nodes that have an order
      • Arc diagram
  • Words
    • How often each is used
      • Term frequency
      • Think twiceWord cloud
    • Which go together
      • Embedding map

Week 2 · Comparison & ranking

Bar chart of counts

How many fall in each category — and because length is the count, the bars start at zero.

Use it when
One categorical variable, and the question is which category is most common.
Watch for
Leaving the categories in alphabetical order. fct_infreq() sorts by count; alphabetical hides the finding.

The code

ggplot(mpg, aes(y = fct_infreq(class))) +
  geom_bar() +
  labs(title = "Cars in the mpg data, by class",
       x = "number of cars", y = NULL)

Week 2 · Comparison & ranking

Lollipop chart

How many fall in each category, as a stem from zero to a dot: a bar with most of its ink taken away.

Use it when
Many categories, where a wall of bars would be mostly ink and the ends of the bars are what matter.
Watch for
Cutting the axis above zero. The stem is a length, so it needs zero just as a bar does. A dot plot has no stem, which is why it does not.

The code

count(mpg, manufacturer) |>
  mutate(manufacturer = fct_reorder(manufacturer, n)) |>
  ggplot(aes(n, manufacturer)) +
  geom_segment(aes(x = 0, xend = n, yend = manufacturer)) +
  geom_point(size = 3) +
  labs(title = "Cars in the mpg data, by manufacturer",
       x = "number of cars", y = NULL)

Week 2 · Comparison & ranking

Waffle chart

Parts of a whole, in units the reader can count: 38 squares of every 100.

Use it when
One share, or two or three, for an audience that should be able to count it.
Watch for
More than three or four categories. Beyond that the grid is noise, and a sorted bar chart says it better.

The code

tibble(cell = 1:100,
       answer = rep(c("Yes", "No"), times = c(38, 62))) |>
  ggplot(aes(x = (cell - 1) %% 10, y = (cell - 1) %/% 10, fill = fct_inorder(answer))) +
  geom_tile(width = 0.85, height = 0.85) +
  coord_equal() +
  labs(title = "Thirty-eight in every hundred said yes",
       x = NULL, y = NULL, fill = NULL) +
  theme(axis.text = element_blank(), panel.grid = element_blank())

Week 1 · The argument in the graph Think twice

Pie chart

Parts of a whole, encoded as angle — one of the channels people read least accurately.

Use it when
Two or three parts, when “about a quarter” is precise enough.
Watch for
Slices of similar size, or more than three of them. Week 1’s ranking of channels is the reason: position beats angle.

The code

mpg |>
  mutate(drv = recode(drv, f = "front", r = "rear", "4" = "four-wheel")) |>
  ggplot(aes(x = "", fill = drv)) +
  geom_bar(width = 1) +
  coord_polar(theta = "y") +
  labs(title = "Cars in the mpg data, by drive",
       x = NULL, y = NULL, fill = NULL) +
  theme(axis.text = element_blank(), panel.grid = element_blank())

Week 2 · Comparison & ranking

Grouped bars

Counts for every combination of two categories, compared within each group.

Use it when
The comparison that matters is between the bars inside one group.
Watch for
More than three or four bars per group. Facet instead, and keep the colours.

The code

as_tibble(UCBAdmissions) |>
  count(Dept, Admit, wt = n) |>
  ggplot(aes(Dept, n, fill = Admit)) +
  geom_col(position = "dodge") +
  labs(title = "Applications to six Berkeley departments, 1973",
       x = "department", y = "applicants", fill = NULL)

Week 2 · Comparison & ranking

Stacked to 100%

The make-up of each group as shares that sum to one. The sizes of the groups are deliberately thrown away.

Use it when
Composition is the point, and how big each group is, is not.
Watch for
Comparing the middle segments. Only the first and the last share a baseline; everything between floats.

The code

as_tibble(UCBAdmissions) |>
  count(Dept, Admit, wt = n) |>
  ggplot(aes(Dept, n, fill = Admit)) +
  geom_col(position = "fill") +
  scale_y_continuous(labels = scales::label_percent()) +
  labs(title = "Share of applicants admitted, Berkeley, 1973",
       x = "department", y = NULL, fill = NULL)

Week 2 · Comparison & ranking

Count grid

How many fall in every combination of two categories, encoded as colour.

Use it when
Many combinations, where the pattern matters more than any exact count.
Watch for
Expecting the reader to read numbers off a colour. If the values matter, print them in the cells, as this one does.

The code

as_tibble(HairEyeColor) |>
  count(Hair, Eye, wt = n) |>
  ggplot(aes(Eye, Hair)) +
  geom_tile(aes(fill = n)) +
  geom_label(aes(label = n)) +
  labs(title = "Hair and eye colour of 592 statistics students",
       x = "eye colour", y = "hair colour", fill = "students")

Alluvial flows

How the same individuals divide across several categorical variables, in sequence.

Use it when
Three or so categorical variables measured on the same cases, where the paths are the finding.
Watch for
Many categories per axis, or axes with no natural order. The ribbons become a tangle, and the order of the axes is itself a claim.

The code

library(ggalluvial)

as_tibble(Titanic) |>
  ggplot(aes(axis1 = Class, axis2 = Sex, axis3 = Survived, y = n)) +
  geom_alluvium(aes(fill = Survived)) +
  geom_stratum() +
  geom_text(stat = "stratum", aes(label = after_stat(stratum)), size = 3) +
  scale_x_discrete(limits = c("Class", "Sex", "Survived")) +
  labs(title = "Everyone aboard the Titanic, by class, sex and survival",
       y = "people", fill = "survived")

Week 2 · Comparison & ranking

Sorted bars

One value per category, ranked. Length is the value, so the axis starts at zero.

Use it when
Comparing amounts across categories. The commonest chart there is, and usually the right one.
Watch for
Cutting the axis above zero. A bar whose length is not its value lies in the strongest channel you have.

The code

tibble(city = names(precip), inches = precip) |>
  slice_max(inches, n = 10) |>
  ggplot(aes(inches, fct_reorder(city, inches))) +
  geom_col() +
  labs(title = "The ten wettest of 70 US cities",
       x = "average rainfall per year (inches)", y = NULL)

Week 2 · Comparison & ranking

Dot plot

One value per category, as a position — so, unlike a bar, the axis does not have to start at zero.

Use it when
The values sit close together and far from zero, so bars would all look the same length.
Watch for
Adding a stem from zero. That turns it back into a length, and a length needs zero again.

The code

tibble(city = names(precip), inches = precip) |>
  slice_max(inches, n = 10) |>
  ggplot(aes(inches, fct_reorder(city, inches))) +
  geom_point(size = 3) +
  labs(title = "The ten wettest of 70 US cities",
       x = "average rainfall per year (inches)", y = NULL)

Week 2 · Comparison & ranking

Diverging bars

How far each category sits above or below a reference, and in which direction.

Use it when
The reference means something: an average, a target, no change.
Watch for
A reference chosen to make one side look large. Say what zero is, in the caption.

The code

mpg |>
  group_by(manufacturer) |>
  summarise(hwy = mean(hwy)) |>
  mutate(gap = hwy - mean(mpg$hwy),
         side = if_else(gap > 0, "above average", "below average")) |>
  ggplot(aes(gap, fct_reorder(manufacturer, gap), fill = side)) +
  geom_col() +
  labs(title = "Highway fuel economy of 15 makes, against the average car",
       x = "miles per gallon above or below the average", y = NULL, fill = NULL)

Week 2 · Comparison & ranking

Slopegraph

Two values per category, and the change between them as the slope of a line.

Use it when
Before and after, or two conditions on the same units. The direction of each line is the finding.
Watch for
More than two points per line, or so many lines that they cannot be labelled.

The code

ggplot(sleep, aes(group, extra, group = ID)) +
  geom_line() +
  geom_point() +
  labs(title = "Extra sleep on two drugs, the same ten patients",
       x = "drug", y = "extra hours of sleep")

Week 3 · Distribution & uncertainty

Strip plot

Every observation in every group, so the reader sees the shape and the n at once.

Use it when
Up to a few hundred points per group. The most honest distribution chart there is.
Watch for
Jittering along the measured axis. Only ever jitter across the categorical one, or the values move.

The code

ggplot(mpg, aes(hwy, class)) +
  geom_jitter(height = 0.2, width = 0, alpha = 0.5) +
  labs(title = "Highway fuel economy, by car class",
       x = "highway miles per gallon", y = NULL)

Week 3 · Distribution & uncertainty

Raincloud

The shape of each group, a summary interval, and the raw points, in one mark.

Use it when
When the reader should see the distribution and the uncertainty about its centre together.
Watch for
Leaving the interval unnamed. ggdist draws a 66% and a 95% interval by default, and the caption has to say so.

The code

library(ggdist)

airquality |>
  mutate(month = fct_inorder(month.name[Month])) |>
  ggplot(aes(Temp, fct_rev(month))) +
  stat_halfeye(adjust = 0.8, scale = 0.5, justification = -0.15) +
  stat_dots(side = "left", scale = 0.5, justification = 1.1) +
  labs(title = "Daily highs at LaGuardia airport, May to September 1973",
       x = "maximum temperature (°F)", y = NULL)

Week 3 · Distribution & uncertainty

Violin

The shape of each group’s distribution, smoothed and mirrored.

Use it when
Groups with enough data for a shape to mean something, where the shape is the point.
Watch for
Small groups. The smoother invents a shape that eight points cannot support — show the points instead.

The code

ggplot(mpg, aes(hwy, class)) +
  geom_violin() +
  labs(title = "Highway fuel economy, by car class",
       x = "highway miles per gallon", y = NULL)

Week 3 · Distribution & uncertainty

Ridgeline

Many distributions on one shared axis, overlapping so their shift can be seen in a glance.

Use it when
Many groups with a natural order, such as months, where the movement of the shape is the finding.
Watch for
Unordered groups. The overlap reads as a sequence that is not there.

The code

library(ggridges)

ggplot(lincoln_weather, aes(`Mean Temperature [F]`, Month)) +
  geom_density_ridges() +
  labs(title = "Daily mean temperature in Lincoln, Nebraska, 2016",
       x = "°F", y = NULL)

Week 3 · Distribution & uncertainty

Box plot

Five numbers per group: the median, the quartiles, and whiskers drawn by a rule the picture does not state.

Use it when
Comparing the middle and spread of many groups at once.
Watch for
Bimodal data. A box has one middle and will draw one where there is none.

The code

ggplot(mpg, aes(hwy, class)) +
  geom_boxplot() +
  labs(title = "Highway fuel economy, by car class",
       x = "highway miles per gallon", y = NULL)

Week 3 · Distribution & uncertainty Think twice

Mean and interval

A mean, and an interval whose meaning the picture does not tell you: SD, SE and CI all look the same.

Use it when
Comparing estimates, with the interval named in the caption every time.
Watch for
Hiding data that could be shown. A few dozen points per group do not need summarising.

The code

ggplot(mpg, aes(hwy, class)) +
  stat_summary(fun.data = mean_se) +
  labs(title = "Mean highway fuel economy by class, ± 1 standard error",
       x = "highway miles per gallon", y = NULL)

Week 3 · Distribution & uncertainty Think twice

Bar with error bars

A mean as the top of a bar, and an interval above it. It hides every observation, the n and the shape.

Use it when
Almost never. Only when the quantity really is a total counted from zero, and the interval is named in the caption.
Watch for
Using it for means at all. Sprays C, D and E here are skewed counts piled near zero; a strip plot or a raincloud shows that, and the bar cannot.

The code

ggplot(InsectSprays, aes(spray, count)) +
  stat_summary(fun = mean, geom = "col") +
  stat_summary(fun.data = mean_se, geom = "errorbar", width = 0.3) +
  labs(title = "Insects left alive after six sprays, mean ± 1 standard error",
       x = "spray", y = "insects counted")

Week 2 · Comparison & ranking

Dumbbell

Two values per category, and the gap between them as the length of a line.

Use it when
Two groups or two conditions measured on every category, where the size of the gap is the finding.
Watch for
Leaving the ends unmarked. Colour them, so the reader knows which end is which before reading any gap.

The code

as_tibble(VADeaths, rownames = "age") |>
  pivot_longer(-age, names_to = c("residence", "sex"), names_sep = " ",
               values_to = "rate") |>
  ggplot(aes(rate, age)) +
  geom_line(aes(group = age)) +
  geom_point(aes(colour = sex), size = 2.5) +
  facet_wrap(~ residence) +
  labs(title = "Deaths a year in Virginia, 1940, men against women",
       x = "deaths per 1,000", y = "age", colour = NULL)

Treemap

Parts of a whole as rectangles nested inside groups, with area as the amount.

Use it when
Many parts in a hierarchy, where which group dominates matters more than any exact share.
Watch for
Comparing two rectangles of similar size. Area is read badly, and the rectangles differ in shape as well; a sorted bar chart ranks them.

The code

library(treemapify)

G20 |>
  filter(country != "European Union") |>
  ggplot(aes(area = gdp_mil_usd, fill = econ_classification,
             label = country, subgroup = region)) +
  geom_treemap() +
  geom_treemap_subgroup_border() +
  geom_treemap_text(place = "topleft", reflow = TRUE) +
  labs(title = "The G20 economies by GDP, grouped by region", fill = NULL)

Histogram

How one continuous variable is spread — after one number you chose and did not print: the binwidth.

Use it when
The first look at any continuous variable.
Watch for
Trusting the default of 30 bins. Try several widths, keep one, and name it in the caption.

The code

ggplot(faithful, aes(eruptions)) +
  geom_histogram(binwidth = 0.2) +
  labs(title = "How long Old Faithful erupts",
       x = "eruption length (minutes, bins of 0.2)", y = "eruptions")

Density curve

The same spread, smoothed. The bandwidth is the binwidth made invisible.

Use it when
Comparing the shapes of a few groups, overlaid.
Watch for
Variables with hard limits. The curve leaks past values that cannot occur, such as below zero.

The code

ggplot(faithful, aes(eruptions)) +
  geom_density() +
  xlim(1, 6) +
  labs(title = "How long Old Faithful erupts",
       x = "eruption length (minutes)", y = "density")

Scatterplot

How two continuous variables move together, one point per observation.

Use it when
Any two continuous variables. The default for a relationship.
Watch for
Reading causation into it. A scatter shows that two things vary together, and nothing about why.

The code

ggplot(mtcars, aes(wt, mpg)) +
  geom_point() +
  labs(title = "Heavier cars go fewer miles per gallon",
       x = "weight (1,000 lb)", y = "miles per gallon")

Week 4 · Relationships & structure

Scatter with a fitted line

A model of the relationship, drawn over the data it summarises. The band is uncertainty about the line, not about the points.

Use it when
The trend is the claim, and the points stay visible beneath it.
Watch for
A straight line through a bend. These points curve, and method = "lm" draws them as if they did not.

The code

ggplot(mpg, aes(displ, hwy)) +
  geom_point() +
  geom_smooth(method = "lm") +
  labs(title = "Bigger engines, fewer miles per gallon",
       x = "engine size (litres)", y = "highway miles per gallon")

Week 4 · Relationships & structure

Bubble chart

A third variable as the area of each point, which readers judge far less accurately than position.

Use it when
When the third variable is context, such as how big each case is, rather than the finding.
Watch for
scale_size(), which maps the value to the radius. scale_size_area() maps it to the area, which is what the eye reads.

The code

ggplot(midwest, aes(percollege, percbelowpoverty, size = poptotal)) +
  geom_point(alpha = 0.4) +
  scale_size_area() +
  labs(title = "College degrees and poverty in 437 Midwest counties",
       x = "% with a college degree", y = "% below the poverty line",
       size = "population")

Week 4 · Relationships & structure

Transparent scatter

Where many points pile up, made visible by letting them add up.

Use it when
Thousands of points, enough that solid ones would hide where most of the data is.
Watch for
An alpha so low that the outliers disappear. They are often the finding.

The code

ggplot(diamonds, aes(carat, price)) +
  geom_point(alpha = 0.05) +
  labs(title = "Size and price of 53,940 diamonds",
       x = "carat", y = "price (US$)")

Week 4 · Relationships & structure

2D bins

How many observations fall in each small square of the plane, as colour.

Use it when
So many points that even transparency turns into a smear.
Watch for
Leaving the legend as “count”. Say what was counted. geom_hex() does the same with hexagons, with the hexbin package.

The code

ggplot(diamonds, aes(carat, price)) +
  geom_bin_2d(bins = 50) +
  labs(title = "Size and price of 53,940 diamonds",
       x = "carat", y = "price (US$)", fill = "diamonds")

Week 4 · Relationships & structure

Small multiples

The same chart once per group, on the same scales, so the comparison is between the panels.

Use it when
A relationship or series that might differ by group. Faceting is conditioning.
Watch for
scales = "free" without telling the reader. It makes every panel look equally steep.

The code

ggplot(mpg, aes(displ, hwy)) +
  geom_point() +
  facet_wrap(~ drv) +
  labs(title = "Engine size and fuel economy, by drive (4, front, rear)",
       x = "engine size (litres)", y = "highway miles per gallon")

Week 4 · Relationships & structure

Scatterplot matrix

Every pairwise relationship among a handful of variables, at once.

Use it when
Exploring, before choosing which relationship to argue about.
Watch for
Publishing it. It is a tool for finding the chart, not the chart.

The code

library(GGally)

ggpairs(mtcars, columns = c("mpg", "disp", "hp", "wt"),
        title = "Four measurements of 32 cars, every pair")

Week 4 · Relationships & structure

Correlation heatmap

Many correlations compressed to colour: the pattern, not the values.

Use it when
Ten or more variables, where the blocks of related ones are the finding.
Watch for
A one-directional palette. r runs from −1 to 1, so it needs a diverging one centred on zero, as here.

The code

cor(mtcars) |>
  as_tibble(rownames = "x") |>
  pivot_longer(-x, names_to = "y", values_to = "r") |>
  ggplot(aes(x, y, fill = r)) +
  geom_tile() +
  scale_fill_distiller(palette = "PRGn", limits = c(-1, 1), direction = 1) +
  labs(title = "How 11 measurements of 32 cars correlate",
       x = NULL, y = NULL)

Week 3 · Distribution & uncertainty

Specification curve

One effect estimated under every defensible choice of analysis, ranked, so the reader sees the spread of answers and not the one that was picked.

Use it when
Any result that depends on choices a reasonable analyst could have made differently: controls, exclusions, codings.
Watch for
Only the choices that agree. The curve is as honest as its set of specifications, so say how the set was drawn up. The specr package adds the panel that shows which choice made which estimate.

The code

controls <- c("cyl", "disp", "hp", "wt", "qsec", "drat")
specs <- map(0:6, \(k) combn(controls, k, simplify = FALSE)) |> list_flatten()

map(specs, \(s) lm(reformulate(c("am", s), "mpg"), data = mtcars)) |>
  map(broom::tidy, conf.int = TRUE) |>
  list_rbind() |>
  filter(term == "am") |>
  mutate(rank = rank(estimate, ties.method = "first")) |>
  ggplot(aes(rank, estimate)) +
  geom_hline(yintercept = 0, linetype = "dashed") +
  geom_pointrange(aes(ymin = conf.low, ymax = conf.high), size = 0.2) +
  labs(title = "A manual gearbox and fuel economy, under 64 sets of controls",
       x = "specification, ranked by estimate",
       y = "extra miles per gallon")

The record, and a model of its trend with the uncertainty around it. The span decides what counts as noise.

Use it when

A span chosen after seeing which one supports the sentence you wanted.

Week 1 · The argument in the graph

Warming stripes

One series as colour alone: no axis, no numbers, only the order and the warmth.

Use it when
A single strong change, for an audience that will not read an axis.
Watch for

Think twice

Radar chart

Each value as a distance along its own spoke, joined into a polygon. The shape, and the area inside it, depend on the order the spokes go round in.

Use it when
A real cycle, where the last spoke belongs next to the first: months, hours, compass bearings. It is the one use its inventor, Georg von Mayr, allowed it in 1877.
Watch for
Comparing profiles whose spokes have no order. Swap two spokes and the areas change, sometimes enough to reverse which case looks biggest. A dot plot or small multiples compare them honestly.

The code

# Each month is a spoke, and the value is a distance along it. Drawn by hand,
# because coord_polar() would bend the straight edges into curves.
tibble(deaths = as.numeric(ldeaths), month = cycle(ldeaths)) |>
  summarise(deaths = mean(deaths), .by = month) |>
  mutate(angle = 2 * pi * (month - 1) / 12,
         x = deaths * sin(angle), y = deaths * cos(angle),
         rim = 1.1 * max(deaths)) |>
  ggplot(aes(x, y)) +
  geom_segment(aes(x = 0, y = 0, xend = rim * sin(angle), yend = rim * cos(angle)),
               alpha = 0.2) +
  geom_polygon(alpha = 0.25) +
  geom_point() +
  geom_text(aes(1.12 * rim * sin(angle), 1.12 * rim * cos(angle),
                label = month.abb[month]), size = 3) +
  coord_equal(clip = "off") +
  labs(title = "Lung disease deaths in the UK, by month",
       x = NULL, y = NULL) +
  theme(axis.text = element_blank(), panel.grid = element_blank())

Arc diagram

Who is connected to whom, with every node on one line in an order that means something, so how far an arc reaches is part of the finding.

Use it when
Nodes that come in an order of their own: chapters, verses, years, the order characters enter a story.
Watch for
An order with no meaning, such as alphabetical. It scatters every cluster along the line, and long arcs then mean nothing.

The code

library(ggraph)

people <- c("Elizabeth", "Jane", "Lydia", "Mr. Bennet", "Mrs. Bennet", "Bingley",
            "Darcy", "Charlotte", "Gardiner", "Collins", "Lady Catherine", "Wickham")

# Every line of the novel that names one of them, and its chapter.
named <- tibble(text = janeaustenr::prideprejudice) |>
  mutate(line = row_number(),
         chapter = cumsum(str_detect(text, "^Chapter \\d+"))) |>
  cross_join(tibble(name = people)) |>
  filter(str_detect(text, fixed(name)))

# Along the line, in the order the novel first names them.
nodes <- named |> slice_min(line, by = name) |> arrange(line) |> select(name)

# Two characters are linked once for every chapter that names both.
in_chapter <- distinct(named, chapter, name)
edges <- inner_join(in_chapter, in_chapter, by = "chapter",
                    relationship = "many-to-many") |>
  filter(name.x < name.y) |>
  count(from = name.x, to = name.y)

  geom_edge_arc(aes(edge_width = n, edge_alpha = n), fold = TRUE) +

Embedding map

Words placed so that words used in similar sentences sit close together. Each word is a long vector, and the page shows two of its directions.

Use it when
Exploring which words a corpus treats as related, before choosing a claim that a count can test.
Watch for
Reading the axes, or the distance between far-apart words. They come from one projection among many, and a different method redraws the map.

The code

library(tidytext)
library(sotu)

words <- sotu_meta |>
  mutate(text = sotu_text) |>
  filter(year > 2000) |>
  unnest_tokens(sentence, text, token = "sentences") |>
  mutate(id = row_number()) |>
  unnest_tokens(word, sentence) |>
  anti_join(stop_words, by = "word") |>
  filter(!word %in% c("applause", "laughter")) |>
  distinct(id, word) |>
  add_count(word) |>
  filter(n >= 40)

# how much more often two words share a sentence than chance says they should
co <- as.matrix(crossprod(cast_sparse(words, id, word)))
pmi <- log(co * sum(co) / outer(rowSums(co), colSums(co)))
pmi[!is.finite(pmi) | pmi < 0] <- 0

# each row is now a word's vector; draw two of its directions
s <- svd(pmi)
tibble(word = rownames(co), n = diag(co),
       x = s$u[, 2] * s$d[2], y = s$u[, 3] * s$d[3]) |>
  slice_max(n, n = 70) |>
  ggplot(aes(x, y, label = word)) +
  geom_point() +
  geom_text(vjust = -0.7, size = 3, check_overlap = TRUE) +
  labs(title = "State of the Union words, placed by the company they keep",
       x = "second dimension", y = "third dimension") +
  theme(axis.text = element_blank(), panel.grid = element_blank())
