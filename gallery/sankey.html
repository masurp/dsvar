Sankey and alluvial flows

A form for showing where a quantity went: how a whole divides, recombines and loses some of itself along the way. It is the only chart type in this gallery that a reader can follow with a finger, which is what it is for.

THE ORIGINAL

Diagram of the thermal efficiency of steam engines by Matthew H. P. R. Sankey, 1898, from Minutes of Proceedings of the Institution of Civil Engineers. Public domain; scan via Wikimedia Commons.

Matthew Henry Phineas Riall Sankey drew this in 1898 to show where the energy in a steam engine actually goes. The answer, visible without reading a number, is: mostly not into work.

How to read it

Follow the flow from one side to the other. The whole quantity enters as a single band and is progressively divided.

The width of every band is the amount flowing through it, and widths are conserved: what leaves a junction equals what entered it.

Branches that peel off are losses. Their width is how much was lost, and where they leave is where in the process it happened.

The narrow band at the end is the useful output. Its thinness relative to the input is the argument.

THE CRITIQUE

01 · Describe

Bands of varying width running left to right, splitting at junctions. Every band is labelled with what it carries. There are no axes and no gridlines, and the only quantitative channel is thickness.

02 · Analyse

Quantity is on width, which is a length and therefore reasonably accurate, but most of the work is done by conservation. Because widths must sum at every junction, the reader can check the diagram against itself. Very few chart types let you do that, and it is why a Sankey feels trustworthy in a way a pie chart does not.

03 · Interpret

The claim is that the losses are the story: the useful output is a thin remnant of what went in, and you can see exactly where the rest went.

04 · Judge

Excellent for a conserved quantity moving through stages, and badly overused for anything else. The form silently promises that the thing being tracked is the same thing throughout and that nothing appears from outside. Point it at categories that merely co-occur and it will still draw a confident picture of a process that does not exist.

THE SAME FORM, DIFFERENT DATA

Unlike most exhibits in this gallery, this section does not redraw the original. Sankey’s engine is a single process measured once; what the form looks like in ggplot is easier to see on data you can load yourself. So this is the same form applied to datasets::Titanic, which ships with R: 2,201 people, by class, sex and survival. It is the categorical version of Sankey’s diagram, usually called an alluvial diagram, and the rule is the same: every band’s width is an amount, and the amounts add up at every step.

Show the R code 
ggplot(titanic, aes(y = Freq, axis1 = Class, axis2 = Sex, axis3 = Survived)) +
  geom_alluvium(aes(fill = Survived), width = .28, alpha = .78, knot.pos = .3) +
  geom_stratum(width = .28, fill = "#f2f0ea", colour = "#d8d3c7", linewidth = .3) +
  geom_text(stat = "stratum", aes(label = after_stat(stratum)),
            size = 2.9, family = dsvar_font()) +
  scale_x_discrete(limits = c("Class", "Sex", "Outcome"), expand = c(.08, .08)) +
  scale_fill_manual(values = c(Died = "#a5a199", Survived = dsvar_accent()),
                    name = NULL) +
  labs(title = "Where 2,201 people went",
       subtitle = "Every band's width is a number of people, and widths are conserved at each step",
       y = "People", x = NULL,
       caption = "n = 2,201 · datasets::Titanic, shipped with R") +
  theme(legend.position = "bottom")

Read a single band with your finger: third class → male → died is the widest path on the chart. First class → female → survived is almost undiminished.

WHAT A STACKED BAR LOSES

Show the R code 
titanic |>
  summarise(n = sum(Freq), .by = c(Class, Survived)) |>
  ggplot(aes(Class, n, fill = Survived)) +
  geom_col(width = .7) +
  scale_fill_manual(values = c(Died = "#a5a199", Survived = dsvar_accent()),
                    name = NULL) +
  labs(title = "The same people, summarised by class alone",
       subtitle = "Correct, readable, and the interaction with sex has vanished",
       x = NULL, y = "People",
       caption = "n = 2,201 · datasets::Titanic") +
  theme(legend.position = "bottom")

Nothing here is wrong, and for the single question “did class matter?” it is the better chart: shorter, easier, no bands to trace. What it cannot show is that third-class women survived at a higher rate than second-class men, because once you collapse to one variable the joint structure is gone. The alluvial answers a question this chart cannot be asked.

THE FORM’S OWN TRAP

Show the R code 
set.seed(11)
fake <- expand_grid(Breakfast = c("Coffee", "Tea"),
                    Commute   = c("Bike", "Tram", "Car"),
                    Weather   = c("Rain", "Dry")) |>
  mutate(Freq = sample(40:400, n()))

ggplot(fake, aes(y = Freq, axis1 = Breakfast, axis2 = Commute, axis3 = Weather)) +
  geom_alluvium(aes(fill = Weather), width = .28, alpha = .7, knot.pos = .3) +
  geom_stratum(width = .28, fill = "#f2f0ea", colour = "#d8d3c7", linewidth = .3) +
  geom_text(stat = "stratum", aes(label = after_stat(stratum)),
            size = 2.9, family = dsvar_font()) +
  scale_x_discrete(limits = c("Breakfast", "Commute", "Weather"), expand = c(.08, .08)) +
  scale_fill_manual(values = c(Rain = "#a5a199", Dry = dsvar_accent()), guide = "none") +
  labs(title = "Nothing flows from your breakfast to the weather",
       subtitle = "Random numbers, three unrelated variables, and a diagram that looks like a process",
       y = NULL, x = NULL,
       caption = "Simulated data. The chart cannot tell, and neither can the reader.")

THE LEFT-TO-RIGHT READS AS CAUSATION

An alluvial diagram of three arbitrary categorical variables is visually indistinguishable from one tracking a real process. The form supplies a direction, a sense of stages, and an implication that what happens later depends on what happened earlier. None of that is in the data. Before drawing one, check that your quantity really is conserved and really does move through those stages in that order. If it does not, you have drawn a claim you cannot support.
