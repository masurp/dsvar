Warming stripes

A century and a half of global temperature, with no axes, no gridlines, no numbers and no legend: one encoding does all of the work. It is the cleanest demonstration in the course that a chart is a claim rather than a table.

THE ORIGINAL

“#ShowYourStripes”, global average 1850–2025, by Ed Hawkins, National Centre for Atmospheric Science, University of Reading. Licensed CC BY 4.0. Data: Met Office HadCRUT5.1.

How to read it

Each vertical stripe is one year, in order: 1850 at the far left, 2025 at the far right. There are 176 of them.

Blue means cooler than the 1961–1990 average for the planet as a whole.

Red means warmer than that same average. The deeper the colour, the further from it.

There is no axis, no scale and no number anywhere. You can see that it got warmer and roughly when; you cannot read off how much, and that is by design.

THE CRITIQUE

01 · Describe

176 vertical stripes of equal width, one per year, ordered left to right. Each is filled with a single colour from a blue-to-red scale. No axis, no tick, no number, no legend, no title. Nothing is encoded except fill, and nothing is labelled at all.

02 · Analyse

Time is on position, which is the most accurate channel available, but it is position without a scale, so it gives order and not distance. Temperature is on colour, which is one of the least accurate channels. The scale is diverging, with its midpoint at the long-term average, so blue and red mean below and above normal rather than simply less and more.

03 · Interpret

The claim is: it used to be colder, it is now hotter, and the change is recent and one-directional. The graphic is not arguing about rate, or cause, or magnitude, because it has given itself no vocabulary to argue about any of them.

04 · Judge

The evidence supports the claim, and the claim is narrow enough that the encoding can carry it. Putting the least accurate channel in charge would be indefensible for a chart that had to be read precisely, and this one never asks to be. That is a choice, not an oversight, and it is why it works.

Describe, analyse, interpret, judge: in that order, and no judging before describing. The same four steps we use on your charts.

THE RECREATION

Everything above is reproducible. The data is a single open CSV, and the chart is about fifteen lines of ggplot once you know the palette. The palette is the part that takes the work, so it is worked out in the open below.

Show the R code 
# The palette is ColorBrewer Blues and Reds, 8 steps each, lightest dropped.
# See "how we know" below — it is not RdBu, which is the usual guess.
blues <- rev(c("#DEEBF7","#C6DBEF","#9ECAE1","#6BAED6",
               "#4292C6","#2171B5","#08519C","#08306B"))
reds  <-     c("#FEE0D2","#FCBBA1","#FC9272","#FB6A4A",
               "#EF3B2C","#CB181D","#A50F15","#67000D")
stripe_pal <- c(blues, reds)

# 16 equal bins across the scale, plus one darker red for the years that run
# off the top of it. Hawkins does the same: 2023 to 2025 are off the scale.
breaks  <- seq(-0.63, 0.99, length.out = 17)
over    <- "#440007"

stripes <- had |>
  mutate(bin = cut(anomaly, breaks, labels = FALSE, include.lowest = TRUE),
         fill = if_else(is.na(bin) & anomaly > max(breaks), over, stripe_pal[bin]))

ggplot(stripes, aes(x = year, y = 1, fill = fill)) +
  geom_col(width = 1) +
  scale_fill_identity() +
  scale_x_continuous(expand = c(0, 0)) +
  scale_y_continuous(expand = c(0, 0)) +
  theme_void()

HOW WE KNOW THAT IS THE PALETTE

The published recipe says the global scale runs from −0.9 °C to +0.9 °C, but binning the data that way does not reproduce the image. So we read the colours off the original instead: sample the centre of each of the 176 stripes, and check what came back.

Show the R code 
library(png)
img <- readPNG(here::here("gallery", "img", "warming-stripes-original.png"))
n   <- nrow(had)

# one pixel from the vertical middle of each stripe
centres <- round((seq_len(n) - 0.5) * ncol(img) / n)
px      <- img[round(nrow(img) / 2), centres, ]
sampled <- toupper(rgb(px[, 1], px[, 2], px[, 3]))

tibble(year = had$year, anomaly = had$anomaly, hex = sampled) |>
  count(hex) |>
  mutate(in_brewer = hex %in% c(stripe_pal)) |>
  summarise(distinct_colours = n(),
            from_brewer      = sum(in_brewer),
            other            = paste(hex[!in_brewer], collapse = " "))
# A tibble: 1 × 3
  distinct_colours from_brewer other  
             <int>       <int> <chr>  
1               17          16 #440007

Sixteen of the seventeen are ColorBrewer Blues and Reds exactly, and they sort in perfect order with the anomaly. The seventeenth, #440007, is darker than the darkest red in either scale and is used by exactly three years: 2023, 2024 and 2025.

WHERE OUR RECREATION DIFFERS, AND WHY

The bin edges above (−0.63 to +0.99, in steps of about 0.101 °C) are fitted to the original rather than documented by it. They reproduce 164 of the 173 on-scale stripes, and all nine misses are before 1935. The likely reason is version drift: Hawkins used HadCRUT 5.1, and the file you can download today is HadCRUT 5.0.2.0, which revises the early record. We could have hidden that by adjusting the edges until they matched; saying so is the more useful lesson.

WHAT IT GIVES UP

The same 176 numbers, encoded to be read rather than felt. This chart answers questions the stripes cannot (how much, how fast, how certain), and it will not survive being printed on a mug.

Show the R code 
# The claim in the title is a PERIOD comparison, not an endpoint one, and the
# difference matters: see the note below this chart.
pre_ind <- mean(had$anomaly[had$year >= 1850 & had$year <= 1900])
recent  <- mean(had$anomaly[had$year >= 2015 & had$year <= 2025])

ggplot(had, aes(year, anomaly)) +
  geom_hline(yintercept = 0, colour = "#e7e3d9", linewidth = .5) +
  geom_ribbon(aes(ymin = lo, ymax = hi), fill = dsvar_accent(), alpha = .18) +
  geom_line(colour = dsvar_accent(), linewidth = .8) +
  labs(title = sprintf("The last decade averaged %.1f °C warmer than 1850–1900",
                       recent - pre_ind),
       subtitle = "Annual anomaly against the 1961–1990 average, with a 95% confidence band",
       x = NULL, y = "°C",
       caption = "n = 176 years · HadCRUT 5.0.2.0, Met Office Hadley Centre / UEA CRU, OGL v3")

A CLAIM WE GOT WRONG FIRST TIME

This title originally read “rose about 1.2 °C between 1850 and 2025”. That is two errors in one line. The endpoint-to-endpoint difference on this series is 1.61 °C, not 1.2, and quoting any endpoint difference on a noisy annual series is a cherry-pick, because it is at the mercy of which two years you happen to stand on. The defensible comparison is period against period, which is what the title now states and what the code above computes. Left here rather than silently corrected, because it is the most common way a true chart acquires a false headline.

Neither chart is the better one. The stripes win an argument in four seconds with an audience that was not going to read an axis; the line chart survives someone who wants to check it. Knowing which job you are doing is the skill. Note, too, that only one of the two can show the uncertainty band at all.

THE SAME DATA, DIFFERENT CHOICES

Three variants, none of them a lie, all of them saying something different. This is what the course means by a visualization being an argument.

Show the R code 
library(patchwork)

strip_plot <- function(fills, title, note) {
  ggplot(tibble(year = had$year, f = fills), aes(year, 1, fill = f)) +
    geom_col(width = 1) + scale_fill_identity() +
    scale_x_continuous(expand = c(0, 0)) + scale_y_continuous(expand = c(0, 0)) +
    labs(title = title, subtitle = note) +
    theme_void(base_family = dsvar_font()) +
    theme(plot.title    = element_text(face = "bold", size = 11, hjust = 0,
                                       margin = margin(b = 2)),
          plot.subtitle = element_text(size = 9, colour = "#5a5a52", hjust = 0,
                                       margin = margin(b = 5)))
}

bin16 <- function(x, brk) {
  i <- cut(x, brk, labels = FALSE, include.lowest = TRUE)
  i[is.na(i) & x > max(brk)] <- 16L
  i[is.na(i) & x < min(brk)] <- 1L
  i
}

i_orig <- bin16(had$anomaly, breaks)

# Stated from the data, not from memory: the third caption is computed, so it
# cannot drift away from the chart it describes when the series is updated.
cross <- function(i) had$year[which(i >= 9)[1]]

seq_pal  <- colorRampPalette(c("#fff5eb", "#7f2704"))(16)   # sequential
rain_pal <- rainbow(16, start = 0.65, end = 0)              # the classic mistake
# A baseline is a choice about what counts as normal. Centre on 1991-2020 and
# most of the record becomes "cold" rather than the recent years becoming "hot".
# The breaks are recomputed over the shifted range: reusing the old ones would
# push 105 of the 176 values off the bottom of the scale, and a demonstration
# that cheats to make its point is the thing this page argues against.
rebased     <- had$anomaly - mean(had$anomaly[had$year >= 1991 & had$year <= 2020])
brk_rebased <- seq(min(rebased), max(rebased), length.out = 17)
i_recent    <- bin16(rebased, brk_rebased)

strip_plot(seq_pal[i_orig],  "Sequential palette",
           "No midpoint, so nothing reads as below normal. Warming becomes an accumulation.") /
strip_plot(rain_pal[i_orig], "Rainbow palette",
           "Invented boundaries where hues change. The eye sees steps the data does not have.") /
strip_plot(stripe_pal[i_recent], "Baseline moved to 1991–2020",
           sprintf("Same numbers, same palette. The blue/red crossover moves from %d to %d.",
                   cross(i_orig), cross(i_recent)))

All three use the identical 176 values. Only the encoding changed. Note how much smaller the baseline effect is than the palette ones: moving the reference period shifts the crossover by a decade, which is worth knowing precisely rather than describing as “it changes everything”. The first draft of this page claimed it made most of history read as cold. It does not, and the caption is now computed from the data so it cannot say so again.
