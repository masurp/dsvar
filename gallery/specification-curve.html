The specification curve

Every defensible analysis at once. Where many analysts hands a dataset to twenty-nine teams, this form does the same job with one team and a loop. This is the closest a chart gets to showing you the space of answers a paper could have reported.

THE ORIGINAL

Figure 1 from Orben, A., & Przybylski, A. K. (2019). The association between adolescent well-being and digital technology use. Nature Human Behaviour, 3, 173–182. Accepted-manuscript version, deposited by the authors at the Oxford University Research Archive. © Orben & Przybylski 2019; the article itself is not open access. Reproduced here at reduced resolution as a quotation for criticism and review — see ORIGINALS.md.

Amy Orben and Andrew Przybylski ran the screen-time-and-wellbeing question across every defensible analysis of the same survey data, and plotted every result. The famous conclusion, that the association is about the size of the association with eating potatoes, only means anything because the whole distribution is on the page. This is the Youth Risk and Behaviour Survey panel; two more, on 40,000 and 20,000 specifications, follow it in the paper.

How to read it

The upper panel is every result, one per analysis, sorted from most negative to most positive. It is a distribution of answers, not a time series.

Each point is one complete analysis: a particular well-being measure, technology measure and set of controls, run to completion. Black is significant, red is not.

The dashed horizontal line is the median of the whole curve: β = −.035 here. It is the paper’s headline number, and it is a summary of the distribution rather than a result of any one analysis.

The lower panel is the recipe. Read straight down from any point and the marked rows tell you exactly which choices produced it.

Vertical bands of marks are the finding. TV Use is marked under the whole right-hand end and nowhere else: the choice of technology measure is doing most of the work.

THE CRITIQUE

01 · Describe

Two stacked panels sharing a horizontal axis. Above: a dense line or cloud of point estimates, ordered by size, usually with intervals. Below: a grid of small marks, one row per analytic option, aligned to the panel above.

02 · Analyse

The horizontal axis is rank, not a variable: it exists only to order the results. That is unusual and it is the trick: it turns a set of unrelated analyses into a distribution you can read the shape of. The lower panel is a lookup table pretending to be a chart, and the alignment between the two is the entire mechanism.

03 · Interpret

The claim is about the robustness of a result rather than its value. A curve that sits entirely on one side of zero says something a single estimate cannot; one that crosses zero says the headline depended on choices the reader never saw.

04 · Judge

It works, with one limit: the curve contains only the specifications its author thought to include, so it looks exhaustive and is not. A specification curve is a much better summary than one regression, and it is still a set of choices about which choices to vary.

THE RECREATION

The survey data behind the original is registration-gated, so this runs the same question on a synthetic stand-in for one wave of pairfam: does adolescent media use go with worse well-being? The specifications are built with specr, which turns the choices into a factorial design and fits every cell: three lines of set-up in place of a hand-written loop.

Show the R code 
# Every combination of these is one defensible analysis. specr expands the
# controls into all four subsets (none, each, both) on its own, and `subsets`
# additionally runs each specification on girls, on boys, and on everyone.
specs <- setup(
  data     = d,
  x        = c("tv_use", "sns_use", "internet_use"),
  y        = c("self_esteem", "depression", "depression_p1", "life_satisfaction_r"),
  model    = "lm",
  controls = c("friend_satisfaction", "age"),
  subsets  = list(gender = c("female", "male"))
)

results <- specr(specs)

specr() fits all of them and returns one row per analysis. The package’s own plot() turns that into a specification curve in a single line, with no ggplot written at all:

Show the R code 
plot(results)

The package default, straight out of plot(results): every estimate ranked by size above, the dashboard of choices below. Fine for looking at your own results. Not yet a figure for a reader: the labels are column names, there is no median, and a model row is shown even though only one model was fitted.

That is not where specr stops, because results$data is an ordinary tibble: one row per specification, with the estimate, its interval, its p-value and the choices that produced it as columns, and anything ggplot can draw can be drawn from it. Here is the same curve built by hand, with plain labels, a median line, the dashboard grouped by kind of choice, and the site’s colours.

Show the R code 
# results$data is a plain tibble, so from here on this is ordinary ggplot:
# every choice below is one plot() makes for you and you can make differently.
r <- as_tibble(results$data) |>
  mutate(subsets = replace_na(as.character(subsets), "all")) |>
  arrange(estimate) |>
  mutate(rank = row_number(),
         sig  = factor(if_else(p.value < .05, "p < .05", "not significant"),
                       levels = c("p < .05", "not significant")))

pal  <- c("p < .05" = dsvar_cat[1], "not significant" = "#a5a199")
med  <- median(r$estimate)

curve <- ggplot(r, aes(rank, estimate)) +
  geom_hline(yintercept = 0, linewidth = .5, colour = dsvar_light$ink_3) +
  geom_hline(yintercept = med, linetype = "22", linewidth = .4,
             colour = dsvar_light$muted) +
  geom_linerange(aes(ymin = conf.low, ymax = conf.high, colour = sig),
                 linewidth = .5, alpha = .55) +
  geom_point(aes(colour = sig), size = 1.1) +
  annotate("text", x = 2, y = med, hjust = 0, vjust = -0.7, size = 3.1,
           colour = dsvar_light$muted,
           label = sprintf("median β = %.3f", med)) +
  scale_colour_manual(values = pal, name = NULL) +
  labs(y = "Standardised β", x = NULL) +
  theme(axis.text.x = element_blank(), legend.position = "top")

# The dashboard. One row per option, a mark wherever that option was used —
# and the marks carry the same colour as the estimate above them, so a band of
# grey in one row is visible as "this choice is where the effect disappears".
nice <- c(tv_use = "TV use", sns_use = "social media use",
          internet_use = "internet use",
          self_esteem = "self-esteem", depression = "depression",
          depression_p1 = "depression (subscale)",
          life_satisfaction_r = "life satisfaction",
          "no covariates" = "no controls",
          friend_satisfaction = "+ friend satisfaction", age = "+ age",
          "friend_satisfaction + age" = "+ both",
          all = "everyone", female = "girls only", male = "boys only")

choices <- r |>
  select(rank, sig, x, y, controls, subsets) |>
  pivot_longer(c(x, y, controls, subsets), names_to = "block", values_to = "choice") |>
  mutate(block  = factor(block, levels = c("x", "y", "controls", "subsets"),
                         labels = c("Predictor", "Outcome", "Controls", "Sample")),
         choice = factor(nice[choice], levels = rev(nice)))

dash <- ggplot(choices, aes(rank, choice, colour = sig)) +
  geom_point(size = .9, shape = 15) +
  facet_grid(block ~ ., scales = "free_y", space = "free_y", switch = "y") +
  scale_colour_manual(values = pal, guide = "none") +
  labs(x = "Specifications, ranked by effect size", y = NULL) +
  theme_dsvar(base_size = 9, grid = "none") +
  theme(axis.text.x = element_blank(),
        strip.placement  = "outside",
        strip.text.y.left = element_text(angle = 0, hjust = 0, face = "bold"),
        panel.spacing.y  = unit(4, "pt"))

# cowplot rather than patchwork: the two panels have different y-label widths,
# and align = "v", axis = "lr" is the reliable way to make the ranks line up.
plot_grid(curve, dash, ncol = 1, align = "v", axis = "lr",
          rel_heights = c(1.4, 2))

144 specifications on n = 3,130 cases. Estimates run from -0.072 to 0.184, median 0.070; 104 of 144 reach p < .05. All variables standardised, so β is comparable across specifications. The four well-being indicators are positively inter-correlated in this file (r = .40 to .92), so they point the same way and a positive β means more media use goes with higher scores on all four. Synthetic pairfam data from Masur’s specification curve tutorial.

WHAT SPECR DOES AND WHAT IT DOES NOT

setup() builds the factorial design and specr() fits it. plot() is the quick look; because the results are a tibble, the figure a reader sees can be whatever you build from it. The package removes the bookkeeping, not the thinking: the list of choices passed to setup() is still the whole argument, and it is the part no function can check for you.

WHICH CHOICE MOVES THE RESULT

The curve tells you how robust the effect is. The dashboard tells you which choice moves it, and the eye is bad at reading that off a grid of marks. Fitting a mixed model to the 144 estimates, with a random intercept per kind of choice, answers it directly.

Show the R code 
vc <- lme4::lmer(estimate ~ 1 + (1 | x) + (1 | y) + (1 | controls) + (1 | subsets),
                 data = r) |>
  lme4::VarCorr() |>
  as.data.frame() |>
  transmute(choice = recode(grp, x = "Which media measure", y = "Which well-being measure",
                            controls = "Which controls", subsets = "Which sample",
                            Residual = "Everything else (residual)"),
            percent = 100 * vcov / sum(vcov))

ggplot(vc, aes(percent, fct_reorder(choice, percent))) +
  geom_col(fill = dsvar_accent(), width = .62) +
  geom_text(aes(label = sprintf("%.0f%%", percent)), hjust = -0.25,
            size = 3.2, colour = dsvar_light$ink_3) +
  scale_x_continuous(expand = expansion(mult = c(0, .12))) +
  labs(title = "The predictor and the sample do the work. The controls do nothing.",
       subtitle = "Share of variance in the 144 estimates attributable to each kind of choice",
       x = NULL, y = NULL) +
  theme(panel.grid.major.y = element_blank())

Any single one of these 144 analyses could have been written up as the result, with a perfectly honest methods section, and the number in the abstract would have run anywhere from -0.072 to 0.184 depending on which one the author ran first. The curve cannot remove that problem, but it makes it visible, which is the most a chart can do.

THE SAME 144, WITHOUT THE RANK AXIS

The critique says the curve’s horizontal axis is rank rather than a variable, and that this is the trick. It is also the cost: sorting by effect size throws the design away, and the dashboard underneath is there to put it back one row at a time. These 144 analyses are a complete 3 × 4 × 4 × 3 factorial, so they do not need reconstructing: they can be laid out on their own axes, every cell filled exactly once. This is close to the grid Steegen and colleagues drew for the multiverse analysis four years before the curve became the standard form, and it answers a different question.

Show the R code 
# The four choices become two nested axes and two facets. Nothing is sorted, so
# every position on this page means something.
pred_lab <- c(tv_use = "TV use", sns_use = "social media use",
              internet_use = "internet use")
samp_lab <- c(all = "everyone", female = "girls only", male = "boys only")
out_lab  <- c(self_esteem = "self-esteem", depression = "depression",
              depression_p1 = "depression (sub)",
              life_satisfaction_r = "life satisfaction")
ctrl_lab <- c("no covariates" = "none", friend_satisfaction = "+ friends",
              age = "+ age", "friend_satisfaction + age" = "+ both")

# Brown-to-teal rather than red-to-green: the sign is the whole point of this
# scale, so it has to survive red-green colour vision deficiency. Neutral at
# zero, and the limits are symmetric so equal-and-opposite betas read as equal.
div <- c("#8c5109", "#cf9a4a", "#e9e4d8", "#5ab4ac", "#01665e")
lim <- max(abs(r$estimate))

# The number inside a cell sits on a fill that runs from near-white to near-
# black, so the label colour is computed from the tile rather than guessed from
# a cut-off on beta: take the actual hex, then whichever of ink and paper wins
# on WCAG contrast.
relative_luminance <- function(hex) {
  ch <- t(grDevices::col2rgb(hex)) / 255
  ch <- ifelse(ch <= .03928, ch / 12.92, ((ch + .055) / 1.055)^2.4)
  as.numeric(ch %*% c(.2126, .7152, .0722))
}
contrast_ratio <- function(a, b) {
  (pmax(relative_luminance(a), relative_luminance(b)) + .05) /
  (pmin(relative_luminance(a), relative_luminance(b)) + .05)
}

g <- r |>
  transmute(
    estimate, sig = p.value < .05,
    predictor = factor(pred_lab[x], levels = pred_lab),
    sample    = factor(samp_lab[subsets], levels = samp_lab),
    outcome   = factor(out_lab[y],  levels = rev(out_lab)),
    controls  = factor(ctrl_lab[controls], levels = ctrl_lab)) |>
  mutate(tile  = scales::gradient_n_pal(div)((estimate + lim) / (2 * lim)),
         label = if_else(contrast_ratio(tile, dsvar_light$ink) >=
                         contrast_ratio(tile, "#ffffff"),
                         dsvar_light$ink, "#ffffff"))

ggplot(g, aes(controls, outcome)) +
  # No tile border, and the gap made by shrinking the tile, so the page's paper
  # shows through rather than a drawn line — the same move as the unit chart in
  # the many-analysts exhibit.
  geom_tile(aes(fill = estimate), width = .94, height = .94, colour = NA) +
  # Significance cannot ride on the fill, which is already carrying magnitude.
  # Outlining only the nulls keeps the extra ink on the minority of cells.
  geom_tile(data = filter(g, !sig), fill = NA, colour = dsvar_light$ink,
            linewidth = .45, linetype = "22", width = .94, height = .94) +
  geom_text(aes(label = sub("^(-?)0", "\\1", sprintf("%.2f", estimate)),
                colour = I(label)), size = 2.5) +
  facet_grid(sample ~ predictor) +
  scale_fill_gradientn(colours = div, limits = c(-lim, lim),
                       name = "Standardised β",
                       guide = guide_colourbar(title.position = "top",
                                               title.hjust = .5)) +
  coord_fixed(expand = FALSE) +
  labs(title = "All 144 specifications, with the analytic choices as the axes",
       subtitle = "One cell per analysis. Dashed outline: not significant at p < .05",
       x = "Controls", y = "Well-being outcome") +
  theme_dsvar(base_size = 10, grid = "none") +
  theme(axis.text  = element_text(size = 8),
        axis.title = element_text(size = 8.5, colour = dsvar_light$ink_3),
        axis.line.x = element_blank(), axis.ticks = element_blank(),
        strip.text = element_text(face = "bold", size = 9),
        panel.spacing = unit(5, "pt"),
        legend.position = "bottom",
        legend.key.height = unit(6, "pt"), legend.key.width = unit(40, "pt"))

The same 144 numbers as the curve, and the same significance test. Positive still means more media use goes with higher scores on all four well-being indicators. Read the bar chart above straight off this picture: the four columns inside every panel are the four control sets and they are the same colour, which is the 0% for controls; the panels deepen from left to right, which is the 38% for the predictor; and they deepen from top to bottom, which is the 34% for the sample. Nothing here is sorted, so every position on the page means something.

Neither the curve nor the bar chart can show this: TV use among girls is the one block on this page that runs the other way, with mean β = −.031 across its 16 cells against +.093 for the same measure among boys. A ranked list has nowhere to put an interaction, and the mixed model above cannot report one either, because it fits main effects only. Add a predictor × sample term to it and 16% of the variance moves out of the residual, which falls from 29% to 22%. The grid did not test for that; it put the cells where an interaction would be visible if there were one, which is what a layout is for.

WHY THIS IS NOT THE DEFAULT

The grid works here because the design is small and completely crossed. Drop one cell and it has a hole; add a choice with twenty levels and it has no shape; and at Orben and Przybylski’s 40,000 specifications there is no grid at all: 144 cells fit on a page and 40,000 do not. It also drops the intervals. The curve draws a confidence interval for every specification; this has room for a point estimate and a significance flag and nothing more. Most of all, it cannot be read as a distribution: the median, the share that crosses zero and the shape of the space of answers, which are the curve’s entire argument, are not in this picture. The curve asks how much the answer moves; the grid asks where the movement comes from.

THE LIMIT OF THE FORM

IT LOOKS EXHAUSTIVE AND IT IS NOT

144 is not every analysis of this data; it is every analysis we thought to list. We varied the predictor, the outcome, two controls and the sample. We did not vary how the scales were built, whether to model the items rather than their mean, how to handle missing data, whether to log the heavily skewed use variables, or whether to fit a multilevel model, and every one of those is defensible. Orben and Przybylski’s curve has the same limit at a much larger scale: forty thousand specifications is still a list somebody wrote. The honest caption states which choices were varied, not just how many analyses were run.

AND THE COUNT ITSELF IS FRAGILE

Two rows of this file have no recorded gender. Passing subsets = list(gender = unique(d$gender)), the obvious thing to write, makes NA a third subset level, and specr then emits the pooled “everyone” specification twice: 192 rows instead of 144, with 48 of them exact duplicates. Nothing errors, the curve looks the same, and the median barely moves. A number in an abstract that says “we ran 192 specifications” can be wrong in a way no plot will show you, which is a good reason to print the design and read it before fitting anything.
